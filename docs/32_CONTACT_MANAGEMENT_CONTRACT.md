# 32_CONTACT_MANAGEMENT_CONTRACT

## 目的

`LL-004` の正本として、会社ごとの複数連絡先、優先連絡先、配信停止、メール作成との接続境界を固定する。

## API

| 操作 | API | 結果 |
|---|---|---|
| 一覧 | `GET /api/companies/{companyId}/contacts` | アーカイブされていない連絡先を、優先順・作成順で返す |
| 追加 | `POST /api/companies/{companyId}/contacts` | 会社へ連絡先を追加する |
| 更新 | `PATCH /api/contacts/{id}` | 担当者名、役職、メール、問い合わせURL、優先、配信停止を更新する |
| アーカイブ | `POST /api/contacts/{id}/archive` | `deletedAt` を記録し、優先状態を解除する |
| 配信停止 | `POST /api/contacts/{id}/unsubscribe` | `isUnsubscribed` と `unsubscribedAt` を記録し、優先状態を解除する |

## データ契約

- 1社に複数の `ContactPerson` を登録できる。
- 優先連絡先は、会社単位のDB advisory lock内で他の優先状態を解除してから設定する。
- 配信停止済み・アーカイブ済みの連絡先は優先連絡先にできない。
- nullable項目へ `null` を送ると、担当者名、役職、メール、問い合わせURLを消去できる。
- 既存の `SalesLead.contactEmail` 等は互換用に残す。新規メールの宛先決定は `ContactPerson` を正本とする。

## メール安全境界

1. 下書き生成時、同一会社の未配信停止連絡先から優先連絡先を解決し、`contactId` と `toEmail` を記録する。
2. 優先連絡先がなければ、未配信停止の先頭連絡先を使用する。
3. 登録済み連絡先が全件配信停止の場合、停止済み連絡先へフォールバックしない。
4. レビュー依頼、再レビュー、承認、送信待ち、手動送信記録では、会社ブロックと連絡先の配信停止を再確認する。
5. 実送信が有効な環境では、providerを呼ぶ直前にも停止状態を再確認する。
6. 配信停止返信を記録した場合、紐づく連絡先にも配信停止を反映する。
7. 連絡先のメール変更後は保存済み宛先との不一致を拒否し、古いアドレスへ送信しない。

## 公開前の境界

- 現在はローカルMVPであり、連絡先APIを保護するログイン・権限管理は未実装である。
- 外部公開前に `LA-002` から `LA-004` を完了し、利用者ごとの認証、権限、操作履歴、データ分離を追加する。

## 画面契約

- 営業リスト画面とメール作成画面は、同じ連絡先管理UIを使用する。
- 営業案件を選ぶと、その会社の連絡先一覧を自動読込する。
- 担当者名、部署・役職、メール、問い合わせURL、優先状態を画面で追加・更新できる。
- 配信停止・アーカイブ操作は選択中の連絡先にだけ適用する。
- 連絡先確認中、または登録済み連絡先が全件配信停止の場合、メール生成・レビュー・承認・送信待ちを操作できない。
- 営業リストで選んだLeadは既存のlocalStorage契約によりメール画面でも復元し、同じ会社の連絡先を表示する。

## 合格条件

1. create/update/archive/unsubscribeが保存後再読込で一致する。
2. 同時に優先設定しても、同じ会社の優先連絡先が1件を超えない。
3. 配信停止済み連絡先をメール宛先・レビュー・承認・送信待ちに使用できない。
4. 優先連絡先の `contactId` と `toEmail` がメール履歴へ残る。
5. 会社ブロック後やレビュー後の配信停止も、後続操作で再検知する。
