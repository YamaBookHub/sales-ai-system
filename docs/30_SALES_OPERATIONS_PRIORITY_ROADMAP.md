# 30_SALES_OPERATIONS_PRIORITY_ROADMAP

## 目的

この文書は、営業メール生成だけで終わらず、候補発見から受注・失注までを安全に管理できる状態を業務上の完成条件として固定する。

技術タスクの変更範囲と合格条件は `27_LUNA_EXECUTION_GUIDE.md`、進捗は `28_REMAINING_WORK_STATUS.md` を正とする。本書は「何を先に完成させるか」の正本である。

## 実装順

### 1. 取得を壊れにくくする

1. LS-002 Makuake fixture test
2. LS-003 CAMPFIRE fixture test
3. LS-004 検索終了理由
4. LS-005 実行中検索の即時停止

LS-007のDB重複防止は完了済み。取得結果が不完全なまま後続の営業機能へ流れないことを優先する。

### 2. 連絡先と配信拒否を正本化する

1. LL-003 詳細編集契約
2. LL-004 Contact CRUD
3. SO-003 配信拒否・重複接触guard

会社と担当者の情報をSalesLeadの自由記述だけに置かない。確認日と情報源を持ち、人間が確認した値を再取得やAI分析で上書きしない。

### 3. 手動送信から次回対応までを通す

1. SO-001 手動送信記録（実装済み。認証後に操作ユーザーを追加）
2. SO-002 返信・次回対応

自動送信は完成条件に含めない。外部で送信した事実を記録し、その文面と宛先を後から追跡できることを先に完成させる。

### 4. 商談パイプラインを完成する

1. SO-004 商談状態・履歴設計
2. SO-005 商談状態・履歴実装

SalesLeadの現在値だけでなく、誰がいつ状態を変更したかを残す。受注と失注を同じ状態で扱わず、失注理由を集計可能にする。

### 5. 集計と大量データへ進む

1. LL-001 server pagination/filter/sort
2. LL-002 全件CSV/TSV
3. SM-001 営業成績

集計はDBを正本とし、画面に読み込んだ一部データを数えない。

### 6. 外部公開前の安全性を完成する

1. LA-002 認証設計
2. LA-003 認証実装
3. LA-004 RBAC・監査
4. LA-005 検索ジョブ所有者・永続化
5. LA-006 バックアップ・復元確認

複数企業へ販売する場合、Userだけでなく組織境界を設計し、組織をまたぐデータ参照をDB/APIの両方で拒否する。

### 7. 販売後に課金・契約を追加する

LP-001でプラン、利用量、請求状態、解約、保持期間、データ出力・削除を設計・実装する。P0/P1と公開前の安全性が完了するまで着手しない。

## 共通ルール

- 自動送信は有効化しない。P0の送信記録は手動送信を対象とする。
- blocked companyまたはunsubscribed contactには、新規文面作成・送信操作前に警告し、送信開始を拒否する。
- 同じ会社だけでなく、正規化した宛先メール・問い合わせURLも重複判定に使用する。
- AI分析、スクレイピング、CSV出力は、人間が確認済みとして保存した連絡先・営業判断を上書きしない。
- 件数・率はサーバー側で集計し、ページ表示中のデータだけを母数にしない。
- 認証前はローカル単一利用者向けと明示し、外部公開しない。

## ローカルMVPの完了

次をすべて満たした状態をローカルMVP完成とする。

1. P0の6機能がTask cardの合格条件を満たす。
2. 実案件を検索、取り込み、分析、メール生成、手動送信記録、返信分類、次回対応登録、商談状態更新まで一周できる。
3. 配信停止・送信禁止・重複接触が自動で防止される。
4. 失敗理由と操作履歴から、利用者が次に何を直すべきか判断できる。
